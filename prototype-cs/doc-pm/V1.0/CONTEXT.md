# OCS 后台一期（PRD V2.0）

在线客服系统「一期后台」的产品需求语境。本文件是该语境的**术语表**，只收录在本语境中有特定含义、易混淆或需要统一口径的词；不写实现细节、不写规格。术语在 `/grill-with-docs` 会话中逐个敲定后写入。

## 角色（Actor）

一期后台区分**人会点**与**代码自动跑**两种动作发起方，不混用同一代号。

**终端用户（C）**：
消息、留言、评价的产出方；后台各模块只在「与后台交互的边界」处出现。对应后端 `MessageSourceUser = 0`。
_Avoid_: 客户、用户（口语可，文档代号统一 C）、U（旧码已弃用）

**客服（A）**：
在线接待执行者——工作台收发消息、撤回/脱敏、挂起/转接/结束会话、待办即时处理。对应后端 `MessageSourceAdmin = 1` 的**普通权限**账号。
_Avoid_: 客服人员、坐席

**客服主管（S）**：
带**更高权限的人**（仍是 admin，source=1）：留言分配/回复、知识库审核与上下线、话术管理、系统设置、转接回退策略配置、差评追踪、待办的主管级操作（催办/一键催评/规则）。与 A 的差别在**权限位**，不在消息来源。
_Avoid_: 系统·管理员（旧称已弃用）、管理员（歧义）、SYS 作主管代号（SYS 已让位给系统 actor，见下）

**系统（SYSTEM）**：
**非人**的自动动作发起方——cron 会话超时关闭、转接 TTL 回退、WS 推送、敏感词过滤、留言 60s 冷却防重、评价超时归跳过、欢迎语/离线语自动推送。对应后端 `MessageSourceSystem = 2`。
_Avoid_: 后端、服务端（实现层叫法）、SYS（旧稿把 SYSTEM 与主管混为 SYS，本稿拆分，见 ADR-0001）

> **审计口径**：任一会话/转接/留言状态迁移必须可区分是 S（人点）还是 SYSTEM（自动）。`C/A/S` = source 0/1/1（S 仅权限更高），`SYSTEM` = source 2。

## 单据（Ticket）

贯穿后台的三类核心领域对象，各有独立状态机（见 PRD §四）。

**会话（Session）**：
一个终端用户与客服之间的一次连续咨询，状态 `wait → accept → pending ⇌ accept → close/cancel`。所有消息、转接、评价都挂在某个会话上。
_Avoid_: 对话、聊天（口语）

**转接单（Transfer）**：
把一个进行中的会话从源客服移交目标客服的单据，状态 `pending → accepted/rejected/cancelled/timeout`，带 TTL 倒计时与到期回退策略。
_Avoid_: 转移、移交

**转接中（会话态）**：
accept 会话存在**未接受（pending）转接单**时所处的中间态。此态下**源客服只读、不可发消息**（用户侧提示"正在为您转接"），用户在窗口内发的消息进队列；目标接受后归属转移、目标接管并可见全部历史。此态是 PRD 原状态机之外新增的会话条件（见转接链拷问）。

**留言（Leave message）**：
用户在客服离线/排队超时时提交的离线诉求，状态 `pending → process → replied`，另可 `invalid ⇌ pending` 可逆。**强制：必须先分配处理人才能回复。**
_Avoid_: 离线消息、工单（工单是 2 期独立模块，非留言）

## 模块简称

11 个后台模块各有一个中文简称，全文（含 UC/AC 编号、mermaid、交叉引用）用简称指代。简称见 PRD §1.1「简称」列。
注意：历史会话 / 客户信息 / 知识库 三者**简称与全称相同**，引用时以编号前缀（如 `UC-客户信息-01`）消歧。

## 其他术语

**敏感词（Sensitive word）**：
词库由**商城平台统一供给**，OCS 客服系统**不自建、不在系统设置里维护词库**。OCS 作为**纯消费方**对接商城词库做消息过滤（用户端 + 客服端实时检测）。商城词库不可达时 **fail-open 放行**（不自留红线最小集、合规真空期靠留痕+审计追溯，见 ADR-0008）。本期「系统设置」不含敏感词库 CRUD（见 ADR-0007）。
_Avoid_: 自建敏感词表、`customer_chat_sensitive_words`（旧 PRD 设想的新建表，已作废）、红线兜底常量（本期不留）
