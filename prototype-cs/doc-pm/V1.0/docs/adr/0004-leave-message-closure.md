# 留言闭环：invalid 对外静默、回复回灌下次会话（不主动推送）

一期留言在 4 态状态机（`pending → process → replied`，`invalid ⇌ pending`）之外定两条对外策略：① **invalid 对用户静默**——invalid 是后台内部质检态，不主动通知用户"无效"，用户侧只保证"提交即回执 + 最终回复送达"，避开"先告知无效、又撤销回复"的可逆矛盾；误判 invalid 靠"撤销 invalid → 回复"流程补救。② **回复不主动推送、回灌下次会话**——留言被回复后不走短信/微信/站内信主动推，而在用户**下次发起咨询时**把历史留言回复作为上下文带出（双方可见"上次留言已这样处理"）。

**为什么**：invalid 可逆，主动告知会产生自相矛盾的体验；回复主动推送要通道成本 + 用户授权，一期取零打扰、零成本的回灌方案。

## 后果（一期接受/需处理的代价）

- **用户不再来 → 看不到回复**：回灌依赖用户主动再发起咨询；一次性问完即走的用户，其留言回复实质石沉大海。一期接受此取舍（换零成本/零打扰）。
- **需同步改 PRD**：§5.2 异步流程 #6「站内信兜底 + 短信/微信」与本决策冲突，改为"回复回灌下次会话、不主动推送"；系统设置「留言通知方式」下拉语义对应调整（从"通知客服/推送"转为回灌开关或移除）。
- 回灌需定义：触发（用户下次建会话时检测未读回复）、展示位置（会话首条系统消息 / 客服侧提示）、多留言累积策略。
