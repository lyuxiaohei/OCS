# 会话为唯一实体：留言 = 会话离线态（不独立成实体）

**决策**：取消「留言」独立实体 / 独立表 / 独立菜单。**会话(session)是唯一服务实体**；「留言」只是会话在**无在线客服**时进入的一个**状态**(offline-pending / 离线待处理)。客服上线后，处于该态的会话走**正常会话分配** → 接入，不再单设留言的"分配处理人 / 回复"流程。

这从根上统一了移动端（同事原型，本就不分会话/留言）与后台：两端面对同一实体（会话），留言只是会话的一个可见态。同时简化数据模型——**无需留言表、无需 origin 字段**，只在会话状态机里加一个离线态。本 ADR 收敛 [[0004-leave-message-closure]]（见下）。

## 会话状态机（含留言态）

```
  新会话 ──(有在线客服)──► 排队等待(wait) ──接入──► 服务中(accept) ──► 关闭/取消
      │                                                        ▲
      └──(无在线客服 / 用户主动留言)──► 离线待处理(留言态) ──────┘
                                         (客服上线 → 走会话分配)
```
- **离线待处理(留言态)**：无在线客服时，会话停留此态；用户消息作为留言内容留存，进待办；移动端线程内联提示"已留言，客服上线后将回复"。
- **客服上线**：此态会话进入**正常分配**（按路由策略）→ 接入 → 服务中。不另设"分配处理人/回复"动作（这些并入正常会话消息收发与路由分配）。
- **用户主动留言**：在线时用户仍可选择留言（异步）→ 会话进入离线待处理态（同上）。即"在线 ≠ 禁止留言"。

## 与既有 ADR 的关系
- **[[0004-leave-message-closure]]**：其留言 4 态机（pending→process→replied，invalid⇌pending）与"分配/回复/标无效"动作**被本 ADR 收敛**——pending 并入会话"离线待处理"，"回复"并入正常会话消息收发，"分配"并入会话路由分配；invalid 作为会话关闭子态保留。0004 的"回复回灌下次会话"在统一模型下自然成立（同一会话线程）。**⚠️ 需据此修订 0004。**
- **[[0003-transfer-lifecycle]]**：转接只发生于"服务中"会话，不受影响。
- **[[0011-org-belong-three-layer]]**：应用端归属仍挂在会话上，不受影响。

## 为什么
- 用户(移动端)心智里只有"我发的消息"，没有"会话/留言"之分；后台也应对齐为单一实体，根除双端割裂。
- 会话与留言的本质都是"用户发起的一次服务联系"，区别仅在"当时有没有客服实时接"——这是**状态**差异，不是**实体**差异。
- 消除留言表 / origin 字段 / 独立菜单 / 独立状态机，模型最简、移动端映射最直接。
- 趁 Go 后端留言表未建（CLAUDE.md 缺口），零成本确立"会话含离线态"的单一模型。

## 后果
- **后台 IA**：「历史会话」+「留言管理」合并为**单一「会话 / 会话记录」列表**；留言作为"离线待处理"状态出现在同一列表的状态 Tab/筛选里，不再有独立留言页。行内字段按状态展示（离线态显留言内容/问题分类，服务中/已关闭显客服/时长/评分）。
- **移动端**：单一消息线程不变；离线时线程进入"留言/等待客服"态并内联提示，客服上线后自动接入继续——对用户即"发了消息，后来有人回了"。
- **后端**：会话状态机加"离线待处理"态 + 上线分配逻辑；无留言表。
- **需修订 [[0004]]**：独立留言状态机/动作被收敛，需同步更新（执行项）。

## ✅ 已确认（PM）
- 取消留言独立实体；留言 = 会话离线态。
- 离线态会话在客服上线后走正常会话分配。
- 「历史会话」+「留言管理」合并为单一会话列表。
- 移动端不区分类型，单一消息线程；"在线 ≠ 禁止留言"。
