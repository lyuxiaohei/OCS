# 操作归属：A 执行 / S 管理·监督 / SYSTEM 自动

一期后台每个操作的发起方按一条原则归位：**`A`（客服）= 单会话内的接待执行**（接入、收发、撤回/脱敏、挂起、发起转接、结束、待办的立即回复/接入）；**`S`（客服主管）= 跨会话或全局的管理·监督操作**；**`SYSTEM`（系统）= 非人自动**（cron、中间件、WS）。犹豫时按"对着某个会话点的 / 管全局的 / 代码自己跑的"三选一定。

**为什么**：`SYS` 拆分后（ADR-0001）每个操作都要落到具体角色；不先定原则会逐模块反复纠结，且 11 模块原型普遍把页面标成"客服A"却混入主管级操作（如待办页 §待办.2.3 自标"主管级"），口径混乱。

## 5 个争议格的裁定

1. **仪表盘**：A + S 都可见（只读），S 为默认入口。修掉"客服主管运营驾驶舱"与 `UC-仪表盘-*=A` 的矛盾，UC 角色列改 `A/S`。
2. **待办·催办 / 一键催评全部 / 设置规则**：**S**（跨人协调、批量群发、全局阈值，均为管理动作）；待办页 A 仅保留「立即回复 / 接入」。
3. **差评追踪（历史会话 & 评价管理）**：**S 发起 + A 补救**——主管定性/记录/结案（质检），客服执行道歉/挽回。`UC-历史会话-06`、`UC-评价-05` 角色列改 `S(发起)/A(补救)`。
4. **转接·配置回退策略（TTL + 三选一）**：**S**（全局策略，类系统设置）；A 在转接页仍可发起/取消/重新转接/催办/查看会话/看负载选目标。
5. **转接·在线客服负载面板**：A + S 都可见（A 选目标、S 全局监控）。

## 后果

- 全文 UC 角色列与状态机角色列按上表重排（grilling 收尾后统一改 PRD）。
- 后端权限模型需区分「客服」「主管」权限位（消息来源同为 admin=1）；批量操作（一键催评）、全局配置（回退策略/阈值/敏感词）须 S 权限校验。
- `SYSTEM` 触发的状态迁移（超时关闭、TTL 回退、冷却防重、超时归跳过）落审计时 actor=system，与人点（admin）严格区分。

## 差评追踪一期范围（Q5 补，2026-06-22）

「S 发起 + A 补救」定了角色，但追踪产出物未定。**一期裁定**：差评追踪只做**记录 + 跟进**——主管在追踪记录里录入回访结果、维护跟进时间线；**补偿方案由主管手动确认**（一期不做自动审批流）；**一期不挂钩客服绩效扣罚**（绩效体系是 2 期）。即一期差评追踪 = 质检留痕 + 人工跟进，非自动惩罚闭环。
