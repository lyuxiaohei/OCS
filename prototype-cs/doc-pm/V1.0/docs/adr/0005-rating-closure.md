# 评价闭环：催评限 2 次、按最终态统计、拆 skipped/expired 差异化催评

一期评价在状态机（`close → pending → done/skipped`）之外定三条：① **催评限次**——每会话催评上限 **2 次**（覆盖"结束即邀 + 隔天提醒"），超限不再催、评价定格；② **统计按最终态**——skipped/已评价都按用户最终归属计一次，转化率 = `最终已评价 / (最终已评价 + 最终已跳过)`，不被催评动作污染；③ **拆 skipped 为两态**——`skipped`（用户主动跳过）与 `expired`（超时未评价），差异化催评：expired 限催 2 次（没看到、提醒有意义），skipped 不主动催或仅 1 次且隔天（尊重明确拒绝）。

**为什么**：原 PRD 的 skipped 混"主动跳过 / 超时"两种触发、催评无上限，导致骚扰用户 + 催评转化率失真。"拒绝"与"忽略"必须分开才能用于绩效分析；催评是温和提醒而非逼评，限次 + 差异化既防骚扰又保 reach。

## 后果

- 评价状态机由 3 态（pending/done/skipped）扩为 4 态（pending/done/skipped/expired），待评价列筛选与计数随之调整。
- 需记录每会话催评次数（达 2 次禁催）+ 区分 skipped/expired 触发来源。
- 催评转化率、满意度等指标分母口径统一为"最终态"，历史数据迁移需注意。
- **待办「待评价-关闭」(UC-待办-07) 衔接细则（Q18 决）**：「关闭」= 主管/客服主动放弃催评，评价定格 **skipped 终态**（计入已跳过分母、不再催评、刷新不复现），并加**二次确认**守卫（"确认关闭？该会话评价将记为已跳过，不再催评"）。skipped 一期**不细分**「用户主动跳过」vs「客服放弃」，后续若运营要区分，加来源标记字段（字段层，不扩状态机）。否决了 B（仅 UI 移除=刷新复现 bug）和 C（新增第三态，一期不值）。

## 催评限次统一口径（Q2 补，2026-06-22）

正文「③ 拆 skipped 为两态」中「expired 限催 2 次 / skipped 仅 1 次且隔天」的表述与「每会话催评上限 2 次」并存，易被读成分桶计数（总数可超 2），开发无法实现。**统一裁定**：催评计数按**会话维度单一封顶 2 次**（不分状态累计，达 2 即定格不再催）；skipped / expired 仅用于决定「该不该催、隔多久催」，**不另开计数桶**。额外规则：**用户主动跳过（skipped）后立即停止催评**（尊重明确拒绝，即使未达 2 次）；expired（超时）可催至满 2 次。一句话：**封顶 2 次，主动跳过提前停**。

## expired 超时阈值（Q6 补，2026-06-22）

评价 expired（超时未评价）的「超时」此前未定阈值，状态无法触发。**裁定**：会话关闭后 **48 小时（2 天）** 用户未提交评价 → 自动由 pending 转 expired（阈值可配）。48h 覆盖「隔天提醒」的合理窗口；过期后仍允许客服在 2 次限内催评。
