# 挂起(pending)恢复归属：默认回原客服，原客服离线即重分

挂起的语义是「**暂停，但仍是我的会话**」（客服主动 `accept→pending`，填原因+恢复时间，暂停无响应超时）。恢复（`pending→accept`）有三触发——①恢复时间到期（定时）②用户发新消息 ③客服手动恢复——PRD §工作台.2.1 守卫「用户行为优先于定时」沿用（任一触发先到即恢复，防双重恢复，不重复拷问）。

**归属规则（本 ADR 新定）**：恢复**默认回原客服**（`admin_id` 不变，与触发方式无关）；**但恢复瞬间若原客服已离线**（下班/断线/转去开会），**不塞回离线客服，进重新分配**——路由引擎按分流策略重分给在线客服，原客服上线后可在历史会话查到。挂起期间用户发的消息**照常进该会话历史、不丢**，恢复后补发给接管方（原客服或重分后的新客服均可见）。

**为什么**：① 在线时回原客服——尊重会话归属、不打断客服已建立的上下文，符合「暂停仍是我的会话」语义；② 离线是硬边界——客服都不在了，「仍是我的会话」落空，强行塞回离线客服等于让用户对着空气发消息，违背「用户发消息即激活」预期；③ 规则一条、trigger 无关，最干净，与 ADR-0003（转接目标离线不硬塞）同一精神。

## 后果

- 恢复动作需探一次原客服在线状态（在线→回原客服；离线→重分）；离线判定与转接共享同一套口径（是否套 2min 宽限属工程细节，非本 ADR 约束）。
- 重分后会话 `admin_id` 变更，须在历史会话客服列体现「原客服 → 重分客服」全链（与 §历史会话「转接双名扩展为全链」一致）。
- 挂起≠放弃：恢复即重分（原客服丢归属）被否（曾考虑的 C 方案），因其偷换了挂起语义，会让客服不敢挂起。
- **挂起期间客服离线：挂起优先于离线宽限（Q7 补，2026-06-22）**：ADR-0003 的「客服离线名下活跃会话宽限 2 分钟重分」针对 **accept 活跃会话**；挂起（pending）会话客服中途离线**不套用离线宽限**——**挂起优先**：会话仍按自己的恢复时间走（暂停语义不变，客服离线不打扰它）。只有**恢复时间到了、原客服还离线**，才按本 ADR「恢复瞬间原客服离线即重分」走。理由：挂起是客服主动暂停、已设恢复时间，若中途离线就提前重分，会破坏「暂停仍是我的会话」预期，并与恢复时间双触发冲突。
