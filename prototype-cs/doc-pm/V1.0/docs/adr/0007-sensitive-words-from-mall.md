# 敏感词由商城词库统一供给，OCS 不自建词库管理

一期 OCS 的敏感词**词库由商城平台的敏感词库统一供给**，OCS 作为消费方对接商城词库做消息过滤（用户端 + 客服端实时检测），**不在 OCS 系统设置里维护词库**。PRD §设置.2.1 的「敏感词库（4 分组 / 20 词 / 批量导入导出）」与 §设置.3 的「新建表 `customer_chat_sensitive_words`」**作废**——实现来源上这是**外部集成**，不是净新建。

**为什么**：商城平台已有统一敏感词库（全站各业务共用），OCS 重复自建会形成两套词库、口径分裂、维护冗余；统一由商城供给保证全站一致。

## 后果

- 设置模块移除「敏感词库」区块（分组/导入导出/新建表）；§1.1 与 §五 的实现来源里，敏感词由「新建表」改为「外部集成」。
- OCS 需对接商城词库（获取方式 = 实时调用 or 同步缓存，属工程决策）；商城词库不可达时的兜底见 Q14。
- ✅ **已决（Q14b）**：命中策略 + 全局过滤开关**归 OCS 租户配**——商城管「哪些词敏感」，租户管「怎么处理」（正交分工）。默认**开关开、策略=替换 \*\*\***（沿用 §设置.2.1 原型默认值）。§设置 保留「全局过滤开关 + 命中策略」两个控件，仅删「敏感词库」区块。
