# 消息审核可见性：撤回/隐藏双向、脱敏单向、原文全留痕

一期工作台三类消息审核操作的用户侧可见性与审计口径：**撤回、隐藏 = 双向**（用户侧也看到处理提示），**脱敏 = 单向**（只客服侧/审计视图脱敏，用户看自己原文明文），三类操作的**原文一律留痕落库**供审计/质检追溯。

| 操作 | 客服侧 | 用户侧 | 原文 |
|---|---|---|---|
| 撤回（客服撤自己的消息）| "⏰你撤回了一条消息" | "客服撤回了一条消息" | 留痕 |
| 隐藏（客服藏用户消息）| "该消息已被管理员隐藏" | "您的消息已被管理员隐藏" | 留痕 |
| 脱敏（客服遮用户消息 PII）| 手机/地址遮蔽 + 黄底橙边 | **看自己原文明文** | 原文落库 |

**为什么**：撤回/隐藏必须双向，否则"回复突然消失"会让用户以为系统出错或客服删帖；脱敏的目的是保护**客服侧/审计视图**里的用户 PII（用户脱口而出的手机号不该明文躺在客服窗），而非防止用户看自己的号码，故用户侧看原文更自然。原文全留痕是客服系统审计/质检/合规的标配。

## 后果

- 用户端需为撤回/隐藏渲染对应系统提示语（用户端 PRD 对齐）。
- 脱敏是**显示层 mask**（客服侧），非物理删除；原文始终落库，审计/质检可查。
- 隐藏采用双向（透明优于偷偷删）；若后续运营反馈激化冲突，可降级为单向（仅 clean 客服侧视图）。
