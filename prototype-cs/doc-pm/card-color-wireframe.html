对比要点：改造前三张卡 banner 颜色各异（橙/绿/红），且按钮同色——类型靠"大色块"识别；改造后三张卡本体完全一致（白底/浅描边/同一按钮样式），类型用右上角小标签传达，颜色节省下来给状态（待发货=橙点）使用。
颜色语义规范 · 颜色只服务"状态"，不服务"类型"
无论订单/商品/优惠券卡，本体永远是白底。下面这套颜色统一用于所有卡片的"状态徽标"和"紧急标记"，与 styles.css 的 status-tag 体系完全对齐。
状态颜色用途
进行中 / 进行中主色 #1677ff待付款、处理中、已发货、进行中会话
已完成 / 成功成功 #52c41a已完成订单、已领取优惠券、质检通过
待处理 / 警告橙色 #fa8c16待发货、待回复、超时预警
异常 / 危险危险 #f5222d退款、取消、质检不通过、紧急工单
已关闭 / 中性灰色 #8c8c8c已关闭会话、已失效优惠券、草稿
同一张订单卡 · 用"状态徽标"表达流转（而非换卡背景色）
这是改造的核心收益：卡片结构不变，只切换右上角状态徽标颜色，即可表达订单全生命周期。竞品千牛/ChatUI 正是如此。

落地规则（确认后据此改 styles.css 与各页面）
卡片本体统一中性
所有卡片：白底 + #f0f0f0 浅描边 + 8px 圆角 + 统一阴影。删除按类型变化的 banner 背景/色条。
类型靠标签+图标
类型用右上角小 pill 标签（订单/商品/优惠券）+ 左上小图标传达，浅底深字，面积小、不抢视觉。
颜色专属状态
5 档状态色（进行/完成/待处理/异常/关闭），复用现有 status-tag，跨卡片类型一致。
按钮统一样式
卡片操作按钮统一为主色描边按钮（白底+主色字+主色边），不再随类型变橙/绿/红。
清理残留 class
删除 .metric-icon.blue/.green/.orange/.purple 这类名存实亡的多色 class，KPI 卡改用中性图标 + 数值颜色。
hex 收敛为 token
admin-workbench / admin-customer-info 里的内联 #faad14/#52c41a 统一替换为 var(--cs-*)，杜绝漂移。
影响范围（待确认后执行）：user-chat.html、admin-workbench.html、admin-customer-info.html、user-faq.html、user-entry.html，以及 styles.css 中 card / metric-icon / mini-avatar 相关段落。不改功能逻辑，仅统一视觉。
