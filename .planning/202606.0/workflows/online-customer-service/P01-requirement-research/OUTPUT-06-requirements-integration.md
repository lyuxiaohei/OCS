## 3. Mock 数据策略

### 3.1 Mock 实现方案

| 方案 | 说明 | 适用场景 |
|------|------|---------|
| 硬编码 Mock | 后端直接返回固定 JSON | 1期 MVP，开发量最小 |
| JSON 文件 Mock | 读取预定义 JSON 文件 | 需要多种场景测试 |
| Mock Server | 独立 Mock 服务 | 接口联调 |

**1期采用方案**: 硬编码 Mock（后端增加 `if config.Mock.Enabled` 分支）

### 3.2 Mock 数据定义

每个外部接口提供 3 种 Mock 场景：

| 场景 | 说明 |
|------|------|
| normal | 正常数据，完整字段 |
| empty | 无数据（新用户/无订单） |
| error | 模拟接口异常 |

### 3.3 Mock 到真实接口的切换机制

```go
// 配置项示例
type ExternalConfig struct {
    MemberAPI  APIConfig `json:"member_api"`
    ProductAPI APIConfig `json:"product_api"`
    OrderAPI   APIConfig `json:"order_api"`
    CouponAPI  APIConfig `json:"coupon_api"`
}

type APIConfig struct {
    BaseURL string `json:"base_url"`
    Mock    bool   `json:"mock"`     // true=使用Mock数据
    Timeout int    `json:"timeout"`  // 超时毫秒数
}
```

## 4. 跨系统数据流

### 4.1 用户进入聊天流程

```
用户点击入口按钮（US-MVP-16）
    ↓ entry_tag 参数
前端跳转聊天页 + 携带 entry_tag
    ↓
后端接收 entry_tag → 匹配路由规则（US-MVP-02）
    ↓
路由规则决定分配客服
    ↓
创建会话 → WebSocket 推送
    ↓
触发自动规则检查（欢迎语/FAQ推荐/离线判断）
    ↓
[并行] 加载客户信息（Mock/真实）
    ├── 会员信息（US-MVP-07）→ 外部: 会员库
    ├── 行为数据（US-MVP-08）→ 外部: 埋点系统
    ├── 交易数据（US-MVP-09）→ 外部: OMS
    └── 服务数据（US-MVP-10）→ 内部: 聚合查询
```

### 4.2 客服发送卡片消息流程

```
客服选择发送卡片（订单/商品/优惠券）
    ↓ 输入 ID
后端查询卡片数据
    ↓ [Mock/真实] 调用外部接口
    ├── 订单 → OMS 接口
    ├── 商品 → 商品库接口
    └── 优惠券 → 营销中心接口
    ↓
后端组装卡片 JSON → 存入 messages 表
    ↓
WebSocket 推送卡片消息 → 用户端渲染
    ↓
用户点击卡片操作
    ├── "查看订单" → 跳转小程序订单页
    ├── "查看详情" → 跳转小程序商品页
    ├── "立即购买" → 跳转小程序下单页
    └── "领取优惠券" → 调用营销中心接口 → 更新卡片状态
```

### 4.3 离线留言处理流程

```
检测所有客服离线
    ↓
触发离线自动回复（US-MVP-22）
    ↓ 发送离线提示消息
    ↓ 发送留言引导卡片
用户填写留言表单（US-MVP-20）
    ↓ 提交
后端保存到 leave_messages 表
    ↓
客服上线后看到待处理留言（US-MVP-06）
    ↓ 分配/回复
客服回复 → 通知用户
```

## 5. 接口安全与限流

### 5.1 外部接口调用安全

| 安全措施 | 说明 |
|---------|------|
| API Key | 每个外部接口配置独立 API Key |
| IP 白名单 | 客服系统出口 IP 加入外部系统白名单 |
| HTTPS | 所有外部接口强制 HTTPS |
| 超时控制 | 默认 3 秒超时，防止级联故障 |
| 重试策略 | 失败重试 1 次，间隔 500ms |
| 降级策略 | 接口不可用时返回缓存/Mock 数据 |

### 5.2 限流配置

| 接口 | 限流策略 | 说明 |
|------|---------|------|
| 会员信息查询 | 10 次/秒/租户 | 缓存 5 分钟 |
| 商品详情查询 | 20 次/秒/租户 | 缓存 10 分钟 |
| 订单详情查询 | 10 次/秒/租户 | 缓存 2 分钟 |
| 优惠券查询 | 10 次/秒/租户 | 缓存 5 分钟 |
| 优惠券领取 | 5 次/秒/用户 | 不缓存 |

## 7. 数据同步与一致性

### 7.1 数据一致性策略

| 数据类型 | 一致性要求 | 实现方式 |
|---------|-----------|---------|
| 客户会员等级 | 最终一致 | 定时同步 + 查询时刷新 |
| 商品信息 | 最终一致 | 缓存 10 分钟 |
| 订单状态 | 最终一致 | 缓存 2 分钟 |
| 优惠券状态 | 强一致 | 每次查询实时获取 |
| 优惠券领取 | 强一致 | 同步调用 + 事务 |

### 7.2 缓存策略

| 数据 | 缓存位置 | TTL | 刷新策略 |
|------|---------|-----|---------|
| 会员信息 | Redis | 5 min | TTL 过期 + 主动刷新 |
| 商品详情 | Redis | 10 min | TTL 过期 |
| 订单详情 | Redis | 2 min | TTL 过期 |
| 优惠券详情 | 不缓存 | — | 每次实时查询 |
